# API Monitor 改进计划

> 版本: 1.1 | 日期: 2026-06-28 | 状态: Phase 1/2/3 全部完成 | 目标: 从可用工具升级到商用级产品

---

## 一、基础加固（安全 + 工程底座） ✅ 已完成

### 1.1 SSL 证书验证 ✅

**现状**: `core/testing.py` 完全禁用 SSL 验证（`CERT_NONE`），所有请求暴露在中间人攻击下。

**改进方案**:
- 默认启用 `ssl.create_default_context()`，验证证书链和主机名
- 在设置面板增加「跳过 SSL 验证」全局开关，存储在 `settings` 表
- 为每个供应商增加独立的「信任自签名证书」选项，应对私有化部署场景
- SSL 验证失败时提供明确错误信息：证书过期 / 主机名不匹配 / 自签名 / CA 不受信任
- 记录 SSL 错误详情到日志，方便排查

**涉及文件**: `core/testing.py`, `core/db.py`, `web/index.html`（设置面板）

### 1.2 API Key 安全存储 ✅

**现状**: API Key 以明文写入 SQLite，任何能访问数据库文件的人可直接读取所有密钥。

**改进方案**:
- 使用 Windows DPAPI（`CryptProtectData` / `CryptUnprotectData`）加密 API Key
- 加密后以 Base64 存入数据库，读取时解密
- 保留明文兼容模式：检测到未加密的旧 Key 时自动迁移为加密格式
- `get_provider_list_formatted()` 和 `_format_provider()` 已有的掩码逻辑保持不变
- 导出功能中 API Key 字段默认脱敏，需手动勾选「包含明文 Key」

**涉及文件**: 新增 `core/crypto.py`, 修改 `core/db.py`, `core/providers.py`

### 1.3 数据库连接管理 ✅

**现状**: 每个函数独立 connect/close，无 context manager，异常时可能泄漏连接。

**改进方案**:
- 引入 `contextlib.contextmanager` 封装 `get_connection()`
- 所有数据库操作使用 `with get_connection() as conn:` 模式
- 添加 `try/finally` 保证连接关闭
- 考虑使用 WAL 模式（`PRAGMA journal_mode=WAL`）提升并发读写性能
- 添加 `PRAGMA foreign_keys=ON` 强制外键约束

**涉及文件**: `core/db.py`

### 1.4 日志与审计系统 ✅

**现状**: `core/` 模块没有任何日志输出，前端推送方法静默吞异常。

**改进方案**:
- 引入 Python `logging` 模块，配置 `RotatingFileHandler`
- 日志路径: `%APPDATA%\.cc-switch-monitor\app.log`
- 日志级别: INFO（正常运行）/ WARNING（可恢复异常）/ ERROR（功能失败）
- 记录所有写操作（增删改、导入、设置切换）为审计日志
- API Key 在日志中强制脱敏（只显示前4后4）
- 前端推送失败时记录 WARNING 而非静默忽略
- 设置面板可选日志级别

**涉及文件**: 新增 `core/logging_config.py`, 修改 `main.py`, `core/*.py`

### 1.5 线程安全 ✅

**现状**: `_stop_flag` 和 `_testing` 无锁保护，存在竞态条件。

**改进方案**:
- 用 `threading.Event` 替换 `_stop_flag` 布尔值
- 用 `threading.Lock` 保护 `_testing` 状态
- `test_all()` 入口检查并原子设置测试状态
- `stop_testing()` 设置 Event 后等待当前测试完成再返回
- 批量测试线程加入 graceful shutdown 检查点

**涉及文件**: `main.py`

### 1.6 SQL 字段白名单 ✅

**现状**: `update_provider()` 动态拼接 dict keys 为 SQL 字段名，无白名单校验。

**改进方案**:
- 定义 `UPDATABLE_FIELDS` 白名单集合
- `update_provider()` 入口处校验所有 key 在白名单内，否则抛出 `ValueError`
- 前端传入数据增加 schema 校验层（可用简单的 dict 校验函数）

**涉及文件**: `core/db.py`, `main.py`

### 1.7 输入校验层 ✅

**现状**: 前端数据直接透传到 SQL，缺少格式校验。

**改进方案**:
- 新增 `core/validators.py`，定义各字段的校验规则
- 端点 URL: 必须是合法 http/https URL，长度 ≤ 500
- 名称: 非空，长度 ≤ 100，去除危险字符
- API Key: 长度 ≤ 2000
- 模型名: 只允许字母、数字、短横线、点、下划线，长度 ≤ 100
- 所有校验失败返回具体的中文错误信息

**涉及文件**: 新增 `core/validators.py`, 修改 `main.py`

## 二、核心功能补全（从能用到好用） ✅ 已完成

### 2.1 并发测试 ✅

**现状**: `test_all_providers()` 串行执行，20 个供应商可能等 10 分钟。

**改进方案**:
- 使用 `concurrent.futures.ThreadPoolExecutor` 实现可配置并发数（默认 3）
- 设置面板可选并发数（1/3/5/10）
- 每个 worker 独立更新数据库和推送前端
- 进度条显示已完成/总数
- 保持「测试中」状态的实时更新

**涉及文件**: `core/testing.py`, `main.py`, `web/js/app.js`

### 2.2 重试与错误分类 ✅

**现状**: 单次请求失败直接标 fail，无重试，错误信息笼统。

**改进方案**:
- 默认重试 2 次，间隔 1s / 2s（指数退避）
- 错误分类为具体类型:
  - DNS 解析失败 → "域名无法解析，请检查端点 URL"
  - 连接超时 → "连接超时(30s)，可能是网络或服务器问题"
  - TLS 握手失败 → "SSL/TLS 证书错误，可能需要在设置中调整"
  - HTTP 401/403 → "API Key 无效或已过期"
  - HTTP 429 → "请求频率过高，已被限流"
  - HTTP 5xx → "服务器内部错误"
  - 无 AI 回复内容 → "API 可达但未返回有效 AI 回复"
- 每种错误附带排查建议

**涉及文件**: `core/testing.py`

### 2.3 测试历史记录

**现状**: 测试结果只保存最后一次，历史数据直接覆盖。

**改进方案**:
- 新增 `test_history` 表:
  ```sql
  CREATE TABLE test_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    provider_id INTEGER NOT NULL,
    status TEXT NOT NULL,          -- ok/fail
    latency INTEGER,               -- 毫秒
    error_type TEXT,               -- 错误分类
    error_detail TEXT,             -- 详细信息
    test_mode TEXT,                -- fast/full
    created_at INTEGER NOT NULL,
    FOREIGN KEY (provider_id) REFERENCES providers(id) ON DELETE CASCADE
  );
  ```
- 每次测试自动写入历史记录
- 保留最近 30 天数据，启动时自动清理过期记录（可在设置中配置保留天数）
- 为延迟趋势图和可用率统计提供数据源
- 添加索引: `CREATE INDEX idx_history_provider_time ON test_history(provider_id, created_at)`

**涉及文件**: `core/db.py`, `core/testing.py`

### 2.4 设置面板

**现状**: 左侧「设置」菜单点击无反应。

**改进方案**:
- 新增设置页面，分区展示:
  - **测试设置**: 自动测试间隔、并发数、超时时间、重试次数
  - **安全设置**: SSL 验证开关、API Key 加密状态
  - **通知设置**: Windows 通知开关、Webhook URL 配置
  - **数据管理**: 导出供应商、备份/恢复数据库、清理历史数据
  - **外观设置**: 语言切换（中/英）
- 设置持久化到 `settings` 表（key-value 结构）
- 修改设置后即时生效，无需重启

**涉及文件**: `web/index.html`, `web/css/style.css`, `web/js/app.js`, `core/db.py`, `main.py`

### 2.5 批量操作 ✅

**现状**: 只能单个操作供应商。

**改进方案**:
- 表格行增加复选框
- 全选/反选按钮
- 批量操作菜单: 批量删除、批量测试、批量设为备用
- Shift+点击区间选择、Ctrl+点击多选

**涉及文件**: `web/index.html`, `web/js/app.js`, `web/css/style.css`

### 2.6 键盘快捷键 ✅

**现状**: 无键盘操作支持。

**改进方案**:
- `Esc`: 关闭弹窗/模态框
- `Enter`: 确认弹窗操作
- `Tab` / `↑` / `↓`: 在表格行间导航
- `Ctrl+F`: 聚焦搜索框
- `Ctrl+T`: 触发快速测试
- `Ctrl+Shift+T`: 触发完整测试
- `Delete`: 删除选中供应商
- 弹窗内焦点陷阱（focus trap）

**涉及文件**: `web/js/app.js`

### 2.7 搜索增强 ✅

**现状**: 只搜索名称和端点。

**改进方案**:
- 搜索范围扩展到: 名称、端点、分类、备注、模型名
- 支持多关键词（空格分隔，AND 逻辑）
- 搜索高亮匹配文本
- 最近搜索历史（下拉建议）

**涉及文件**: `web/js/app.js`

## 三、商业增值（差异化卖点） ✅ 已完成

### 3.1 自动故障切换（Failover）

**现状**: 供应商挂掉后用户必须手动切换。

**改进方案**:
- 当「当前」供应商测试失败时，自动按优先级切换到最优备用供应商
- 切换策略:
  - 优先级排序: 最近测试 OK → 延迟最低 → 角色为「备用」
  - 切换动作: 写入 `~/.claude/settings.json` + 更新数据库 role
  - 切换后发送通知告知用户
- 配置选项:
  - 启用/禁用自动切换
  - 切换前需确认（弹窗 vs 静默）
  - 最大连续切换次数（防止全部 fail 时无限切换）
  - 切换冷却时间（防止频繁切换）
- Failover 事件写入审计日志
- 在供应商列表中标记「Failover 候选」顺序

**涉及文件**: 新增 `core/failover.py`, 修改 `main.py`, `core/testing.py`, `web/js/app.js`

### 3.2 延迟趋势与可用率仪表盘

**现状**: 只显示最后一次测试的延迟数值。

**改进方案**:
- 在右侧详情面板增加「趋势」标签页
- 折线图展示选定供应商过去 24h / 7d / 30d 的延迟变化
- 时间范围切换: 24h / 7d / 30d
- 关键指标卡片:
  - 平均延迟（ms）
  - P95 延迟（ms）
  - 可用率（%）= OK 次数 / 总测试次数 × 100
  - 最近一次故障时间
- 多供应商对比模式: 勾选多个供应商在同一图表叠加对比
- 图表使用内嵌的轻量 Canvas 绘制，不引入外部图表库（保持打包体积小）
- 数据源: `test_history` 表

**涉及文件**: `web/index.html`, `web/css/style.css`, `web/js/app.js`（新增 Canvas 图表模块）, `main.py`（新增历史查询 API）

### 3.3 通知系统

**现状**: 无任何通知机制，用户必须盯着界面看。

**改进方案**:
- **Windows Toast 通知**（使用 `win10toast_click` 或 `plyer`）:
  - 供应商从 OK 变为 Fail → 发送告警通知
  - 自动 Failover 发生 → 发送切换通知
  - 全部测试完成 → 发送汇总通知（X 正常 / Y 失败）
- **Webhook 通知**（HTTP POST）:
  - 配置 Webhook URL（支持 Slack / 飞书 / 钉钉 / 自定义）
  - 事件类型可选: 状态变化、Failover、测试完成
  - 消息模板: Markdown 格式，包含供应商名、状态、延迟、时间
  - 发送失败时记录日志，不阻塞主流程
- **应用内通知中心**:
  - 右上角铃铛图标 + 未读红点
  - 点击展开通知列表（最近 50 条事件）
  - 事件类型: 状态变化、Failover、导入完成、测试完成

**涉及文件**: 新增 `core/notifications.py`, 修改 `main.py`, `web/index.html`, `web/js/app.js`

### 3.4 自动定时测试

**现状**: 用户必须手动点击测试按钮。

**改进方案**:
- 后台定时器线程，按配置间隔自动触发全量测试
- 可选间隔: 关闭 / 5分钟 / 15分钟 / 30分钟 / 1小时
- 定时测试使用静默模式（不弹 Toast，只更新状态和写历史）
- 状态变化时才触发通知
- 顶部状态栏显示「下次自动测试: XX:XX」倒计时
- 用户手动测试时重置倒计时
- 应用最小化到托盘时仍保持定时测试

**涉及文件**: 新增 `core/scheduler.py`, 修改 `main.py`, `web/js/app.js`

### 3.5 数据导出与备份

**现状**: 无法导出数据，无备份机制。

**改进方案**:
- **导出供应商列表**:
  - 格式: CSV / JSON
  - 可选字段: 名称、端点、角色、状态、延迟、分类、备注
  - API Key 默认脱敏，可选包含（需二次确认）
- **导出测试历史**:
  - 按供应商 / 按时间范围筛选
  - 格式: CSV（兼容 Excel 打开）
  - 字段: 供应商名、时间、状态、延迟、错误类型、错误详情
- **数据库备份**:
  - 一键备份: 复制 `providers.db` 到用户指定目录
  - 自动备份: 每天首次启动时自动备份到 `%APPDATA%\.cc-switch-monitor\backups\`
  - 保留最近 7 份自动备份（滚动删除旧的）
- **数据库恢复**:
  - 从备份文件恢复（需确认覆盖）
  - 恢复前自动备份当前数据库

**涉及文件**: 新增 `core/export.py`, `core/backup.py`, 修改 `main.py`, `web/js/app.js`

### 3.6 多 Profile 支持 ✅

**现状**: 只管理一套 `~/.claude/settings.json`。

**改进方案**:
- 支持创建多个配置 Profile（如: 工作项目A、个人项目B）
- 每个 Profile 关联独立的 `settings.json` 路径
- Profile 切换器在顶部状态栏
- 切换 Profile 时自动加载对应的供应商子集和设置
- 数据库中按 `profile_id` 分区存储

**涉及文件**: `core/db.py`, `core/providers.py`, `main.py`, `web/index.html`, `web/js/app.js`

### 3.7 自动更新 ✅

**现状**: 无版本检查和更新机制。

**改进方案**:
- 启动时检查远程版本信息（GitHub Releases API 或自建端点）
- 发现新版本时在应用内提示（非阻塞横幅）
- 一键下载: 打开浏览器到下载页面
- 显示 Changelog 摘要
- 可关闭自动检查

**涉及文件**: 新增 `core/updater.py`, 修改 `main.py`, `web/js/app.js`

## 技术约束

- 保持 PyInstaller 单文件打包，不引入过大的依赖
- 所有新模块必须有单元测试
- 前端保持单文件 HTML + 单 JS + 单 CSS 结构
- 数据库 schema 变更必须有迁移脚本，兼容旧数据
- Neo-Brutalist UI 风格保持一致
