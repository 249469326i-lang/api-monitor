# 设计：Claude 供应商存储独立于 cc-switch

**日期**：2026-06-24
**状态**：已通过设计评审，待写实现计划
**范围**：仅 Claude（`app_type` 为 `claude` / `claude-desktop`）供应商迁出 cc-switch 数据库；Codex 不变

---

## 1. 背景与目标

### 1.1 现状
`cc_switch_monitor.py` 目前把所有供应商（Claude 与 Codex）都存在 cc-switch 的 SQLite 库 `~/.cc-switch/cc-switch.db` 中（表 `providers` + `provider_endpoints`）。切换供应商时再写 `~/.claude/settings.json` 或 `~/.codex/`。

### 1.2 目标
让 monitor **完全独立代理 Claude Code 的 API 配置**，不再依靠 cc-switch：
- Claude 供应商列表存放在 monitor 自己的库
- Codex 供应商本次不迁移，仍读 cc-switch
- 首次启动自动从 cc-switch 导入现有 Claude 供应商
- "当前在用"的供应商由读 `~/.claude/settings.json` 比对得出，不信任库内 `is_current` 标志

### 1.3 非目标
- 不迁移 Codex
- 不改 UI 布局
- 不改供应商的 JSON 配置格式（`settings_config` 结构不变）

---

## 2. 实现路线

**路线 A：按 app_type 路由到不同库（已选定）**
新增 `OWN_DB_PATH`，加 `_db_path_for(app_type)` 帮助函数。所有 Claude 路径的 SQL 改用 `OWN_DB_PATH`，Codex 路径继续用 cc-switch 库。`read_claude_providers()` 分别查两个库再合并。

选定理由：复用现有全部 SQL 代码，函数签名不变，风险最低；现有代码本就按 `app_type` 分支，路由到不同库是该模式的自然延伸。

---

## 3. 数据层与存储位置

### 3.1 新常量
```python
OWN_DIR       = os.path.expanduser(r"~\.cc-switch-monitor")
OWN_DB_PATH   = os.path.join(OWN_DIR, "providers.db")
CC_SWITCH_DB_PATH = os.path.expanduser(r"~\.cc-switch\cc-switch.db")  # 仅 Codex 用
AUDIT_LOG_PATH = os.path.join(OWN_DIR, "audit.log")  # 从 ~/.cc-switch/ 迁出
```
倾向把原 `DB_PATH` 改名为 `CC_SWITCH_DB_PATH` 以避免误读。

### 3.2 建库初始化 `ensure_own_db()`
首次访问 Claude 路径前调用（程序启动时调一次），用 `CREATE TABLE IF NOT EXISTS` 建两张表，schema 与 cc-switch 一致（保证迁移可整行 INSERT）：

- `providers(id TEXT PK, app_type, name, settings_config TEXT, website_url, category, created_at INT, notes, meta TEXT, is_current INT, in_failover_queue INT, provider_type, sort_index INT)`
- `provider_endpoints(provider_id, app_type, url, added_at INT)`

只建 Claude 用到的两张表；`provider_health` / `stream_check_logs` 暂不建。

### 3.3 路由帮助函数
```python
def _db_path_for(app_type: str) -> str:
    return OWN_DB_PATH if app_type in ("claude", "claude-desktop") else CC_SWITCH_DB_PATH
```
所有 `sqlite3.connect(f"file:{DB_PATH}...")` 调用点替换为 `_db_path_for(app_type)`。

### 3.4 写回 settings.json
逻辑完全不变（本就独立于 DB 来源）。

## 4. 首次启动自动导入

### 4.1 触发条件
`ensure_own_db()` 建好表后，检查标记文件 `~/.cc-switch-monitor/.imported`：
- 标记文件不存在 + 自有库 Claude 行数为 0 + cc-switch 库存在 → 执行一次导入，完成后写入标记文件。
- 标记文件存在 → 不再自动导入（即使用户把自有库清空了也不重新拉），避免清空操作被重启覆盖。需要再同步时走 UI 的「从 cc-switch 导入」按钮（幂等）。

### 4.2 导入函数 `import_claude_from_ccswitch()`
1. 以只读打开 cc-switch 库，查 `app_type IN ('claude','claude-desktop')` 的所有行 + 对应 `provider_endpoints`。
2. 用 `INSERT OR IGNORE` 整行写入自有库（保留原 id、created_at、settings_config 等全部字段，不重建）。
3. 同样 `INSERT OR IGNORE` 端点行。
4. 写审计日志：`IMPORT n=12 from=cc-switch`。
5. 任何单行失败不中断整体，累计失败数记入日志。

### 4.3 幂等性
`INSERT OR IGNORE` + 主键 id 重复时跳过，重复触发不产生重复数据。UI 上可选的「从 cc-switch 导入」按钮可安全重复点击。

### 4.4 不导入 is_current
导入后立即由 §5 的 settings.json 比对覆盖 `is_current`，避免把 cc-switch 的旧标记带过来。

## 5. 当前供应商检测

### 5.1 核心函数 `sync_current_from_settings(providers)`
每次 `read_claude_providers()` 返回前调用，不写库、只改内存标记。

### 5.2 比对键
读 `~/.claude/settings.json` 的 `env`，取
- `base = normalize_provider_url(env.ANTHROPIC_BASE_URL)`
- `key = env.ANTHROPIC_AUTH_TOKEN or env.ANTHROPIC_API_KEY`

与每个 Claude 供应商的 `settings_config.env` 同两字段比。

### 5.3 匹配规则（按强度降序，命中即停）
遍历顺序与 `read_claude_providers()` 返回顺序一致（`sort_index, created_at, id`），首个命中者生效。

1. `base` 非空 且 `base` 相等 且 `key` 相等 → 精确命中，`is_current=True`
2. `base` 非空 且 `base` 相等（key 不同）→ `is_current=True`，warning "key 不匹配"
3. settings.json 的 base 不匹配任何供应商 → 全部 `is_current=False`，全局提示 "当前 settings.json 不指向库内任何供应商"

### 5.4 何时调用
`read_claude_providers()` 最后、合并 Codex 之后，只对 Claude 项应用。Codex 的 `is_current` 仍信任各自库。

### 5.5 写回关系
`switch_provider()` 切 Claude 时已写 settings.json；切完**不必**回写自有库 `is_current`——下次 `read_claude_providers()` 自动比对出来。消除"两个库 is_current 不一致"隐患。

### 5.6 性能
比对在内存完成，无额外 IO；settings.json 本就在 `read_claude_providers` 流程里读。`POLL_INTERVAL_MS=3000` 轮询每次都比对，能发现用户在 Claude Code 外手动改 settings.json 的情况。

## 7. UI 影响与可见变化

### 7.1 UI 层零改动
`read_claude_providers()` 返回的列表结构、字段、`app_type` 值全部不变，tkinter 表格、详情面板、右键菜单、新建/编辑表单都无需调整。

### 7.2 用户可见的运行时变化
1. **首次启动**：自动从 cc-switch 导入 Claude 供应商，列表与之前一致（无感迁移）。Codex 行照常显示。
2. **启动后**：`is_current` 标记来自 settings.json 比对。
3. **切换供应商**：行为不变，仍写 `~/.claude/settings.json`。下次轮询自动刷新标记。
4. **增删改 Claude 供应商**：行为不变，落到 monitor 自己的库。

### 7.3 新增 UI 元素（最小化）
- 菜单/按钮「从 cc-switch 导入」——调用 `import_claude_from_ccswitch()`，幂等可重复点。建议加，否则首次导入后没有再同步途径。
- 不需要"导出"或"迁移完成"提示弹窗——静默即可。

### 7.4 不再可见
- 程序不再依赖 cc-switch 进程（Claude 侧连 db 都不读了）。
- `~/.cc-switch/monitor-audit.log` 停止更新（迁到 `~/.cc-switch-monitor/audit.log`），旧文件保留。

## 8. 错误处理与边界

### 8.1 建库失败
`ensure_own_db()` 若 `sqlite3.connect` 或 `CREATE TABLE` 失败 → 记日志、返回 `(False, msg)`，调用方按现有"数据库操作失败"格式提示。不静默，因为后续所有 Claude 操作都会失败。

### 8.2 导入边界
- cc-switch 库不存在 → 静默跳过（视为全新安装），不报错。
- cc-switch 库加密/损坏 → `sqlite3.connect` 抛异常，捕获、记日志、返回 0 导入数，不阻断启动。
- 部分行 `settings_config` 损坏 → 整行 INSERT 不依赖解析，原样存入；后续读取时该供应商显示为空配置（与现状一致）。
- 自有库已有同 id → `INSERT OR IGNORE` 跳过、不覆盖。强制覆盖选项本次不做。

### 8.3 比对边界（sync_current_from_settings）
- `settings.json` 不存在或读失败 → `base=""`, `key=""` → 全 False，加全局警告 "未读取到 ~/.claude/settings.json"。不报错。
- `settings.json` 无 `env` 或无 `ANTHROPIC_*` → 同上全 False。
- 多个供应商 base+key 相同 → 命中第一个（按 sort_index/created_at），其余加 warning "与当前供应商配置重复"。复用现有 `detect_provider_config_warnings()`。

### 8.4 并发与文件锁
- 自有库与 cc-switch 库都是 SQLite，现有代码已用 `timeout=10` + `uri=True`。轮询读 `mode=ro`，写 `mode=rw`。保持一致。
- `ensure_own_db()` **只在程序启动时调一次**，写操作前不再重复调——失败则启动时就暴露。

### 8.5 数据完整性
- 自有库不建 `provider_health` / `stream_check_logs`。`delete_provider()` Claude 分支那两条 DELETE 用 `try/except sqlite3.OperationalError: pass` 包裹。这是唯一需要新增 try/except 的地方。
- 外键：不强制，沿用手动删除关联表模式。

### 8.6 审计日志迁移
- 新路径 `~/.cc-switch-monitor/audit.log`，目录由 `ensure_own_db()` 一并 `makedirs`。
- 日志 handler 初始化时若新目录创建失败 → 回退到旧路径 `~/.cc-switch/monitor-audit.log`，保证日志不丢。

**`ensure_own_db`**
