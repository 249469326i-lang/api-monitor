# CC Switch Monitor Test Speed and Layout Fix Design

Date: 2026-06-23

## Context

Users report three related usability problems in `CC-Switch-Monitor`:

- Provider testing is too slow.
- Some table content is clipped, especially the masked API key value where the last letter is only partly visible.
- Dragging the center `PanedWindow` sash does not make the left table content expand with the pane.

The project is a Tkinter desktop app centered on `cc_switch_monitor.py`. It is not currently inside a git repository, so this design cannot be committed from this workspace.

## Root Cause

Testing is slow because `smart_test_provider()` runs a broad matrix after its initial probe: up to 10 models across all protocols and endpoint suffixes, with each HTTP request allowed to take up to `HTTP_TIMEOUT` seconds. After HTTP testing, `_run_provider_test()` and `_test_all()` may also run a Claude CLI probe with `CLI_PROBE_TIMEOUT` set to 60 seconds.

The key clipping issue comes from fixed Treeview column widths. The `key` column is 75 px wide, and only the `detail` column stretches. This leaves no room for the masked key when font metrics or scaling differ.

The sash issue comes from only setting the initial split position with `_set_sash_position()`. There is no binding that reacts to the table pane resizing after the user drags the sash, and there is no table-column layout function that redistributes available width.

## Design

### Testing Modes

Add two explicit test modes:

- Fast test: the default mode for the toolbar button and double-click/context-menu provider testing.
- Full test: a diagnostic mode for users who want the complete matrix and CLI feedback.

Fast test should:

- Test only the highest-probability protocol and suffix combinations.
- Stop as soon as a successful HTTP combination is found.
- Skip CLI probing by default.
- Keep the UI progress state and existing result display format.

Full test should:

- Preserve the current broad HTTP matrix behavior.
- Preserve CLI probing after HTTP testing.
- Remain available from a separate explicit control, so users can choose completeness when needed.

### Table Layout

Add a dedicated table-layout helper that recalculates column widths from the current Treeview width. The helper should:

- Reserve stable minimum widths for all columns.
- Give `key` enough width for masked keys without clipping.
- Allocate extra width mainly to `name`, `endpoint`, and `detail`.
- Avoid changing row height or visual theme.

### Sash Resize Behavior

Bind the left table container or Treeview to resize events and debounce column recalculation with `after()`. When the user drags the center sash, the left pane width changes, the table receives a configure event, and the columns are recomputed for the new width.

The initial sash positioning remains, but it should not be the only layout pass.

## Scope

In scope:

- Add fast/full test selection.
- Make fast test the default.
- Preserve full diagnostic testing.
- Fix Treeview key clipping.
- Recalculate table columns after resize/sash drag.

Out of scope:

- Changing provider database schema.
- Changing provider creation/editing flows.
- Redesigning the full visual style.
- Adding new network dependencies.

## Verification

Manual verification:

- Launch the app and confirm the default test action completes faster for a provider with a working high-probability endpoint.
- Run full test and confirm it still records HTTP matrix and CLI feedback.
- Confirm masked keys render fully in the table.
- Drag the center sash left and right and confirm the table columns expand or shrink with the left pane.

Automated/basic verification:

- Run Python syntax compilation for `cc_switch_monitor.py`.
- If practical, add or run focused tests for test-mode selection logic without making live network calls.
